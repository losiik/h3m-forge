# Два простых сценария для проверки MCP

Каждый блок ниже — готовый запрос для нового чата с подключённым h3m-forge.
Нужна именно генерация через MCP. Эти тексты не являются готовыми картами.

## Сценарий 1: «Остров сокровищ»

Создай через MCP h3m-forge небольшую одиночную карту HotA 1.8.0 «Остров
сокровищ» по мотивам приключения Джима Хокинса. Цель — найти тайник и
победить мятежников. Ориентир: 30–60 минут игры.

Пять глав: гавань → захваченный склад → старый форт → тайник. От склада
отходит необязательная ветка к убежищу Бена Ганна. Ветка не должна быть
условием победы: после неё игрок продолжает путь к форту.

На складе бой освобождает нескольких стрелков, которые помогут в следующих
сражениях. У Бена Ганна за дополнительный бой получаем один полезный артефакт
для последующих боёв. Старый форт охраняет основной проход; отдельная награда
за него не обязательна. В тайнике — самый трудный бой, завершение финальной
главы должно приводить к победе. Мятежников представь поддерживаемой охраной,
без собственного сценарного ИИ для нового героя.

Используй поддерживаемый архипелаг 72×72, balance_profile="fixed", seed=130901,
небольшую армию без существ седьмого уровня и без Воскрешения. Стартовая армия
— отдельная отправная точка, дополнительные бонусы получаются за испытания.
Не добавляй ожидание денег, обязательные сборы артефактов и немедленную сдачу
полученных воинов. Сделай последовательность глав обязательной средствами
генератора; длинное описание не должно заменять маршрут.

Порядок работы: сначала project_status и scenario_catalog. Проверь схему
generate_scenario; если доступен ресурс h3m://scenario-example, прочитай его.
Через catalog_search/catalog_get выбери только нужных существ и артефакты
с ruleset="hota_1.8.0", учитывая scenario_support; через skill_catalog проверь
выбранные навыки. Не выгружай всю энциклопедию в чат. Передай законченную
спецификацию в generate_scenario. Проверь полученный файл через inspect_map,
inspect_encounters и preview_map. Если PNG клиент не показывает, используй
текстовые данные обзора. Верни путь к .h3m и замечания проверок.

Работай средствами MCP без Computer Use и без изменения кода проекта.
Если нужной функции нет, используй поддерживаемый аналог и явно поясни
замену. Не утверждай, что карта пройдена человеком или баланс доказан.

## Сценарий 2: «Снежная королева»

Создай через MCP h3m-forge небольшую одиночную карту HotA 1.8.0 «Снежная
королева»: Герда отправляется освобождать Кая. Адаптируй сказку к северному
архипелагу. Цель по длительности — 30–60 минут.

Пять глав: родная деревня → лагерь разбойников → замёрзший пролив → ледяной
дворец. От лагеря отходит необязательная ветка к дому лапландки, которая
не должна быть условием прохода к дворцу.

Победа в лагере освобождает небольшое подкрепление. Возле дома лапландки
дополнительный бой охраняет запас маны и одно полезное боевое заклинание
из разрешённых генератором; испытать его можно в проливе. Основной путь
должен быть проходим и без этой награды. Во дворце — сильнейший отряд
ледяных стражей. Освобождение Кая отрази завершением финальной главы
с настоящим условием победы. Не требуй особых скриптов спасения персонажа.

Используй поддерживаемый архипелаг 72×72, balance_profile="fixed", seed=130902,
небольшую армию без существ седьмого уровня и без Воскрешения. Не делай
обязательных платежей, ожидания найма и сдачи только что полученной награды.
Вознаграждай дополнительные испытания; бой за проход сам по себе полезен.
Подчеркни снег, скалы и движение на север доступными средствами генератора.

Порядок работы: project_status, scenario_catalog, схема generate_scenario;
при доступности — ресурс h3m://scenario-example. Подбери существ и заклинание
через catalog_search/catalog_get с ruleset="hota_1.8.0", навыки — через
skill_catalog. Учитывай scenario_support и ограничения схемы. У героя должны
быть подходящие навыки для использования выбранного заклинания. Не выгружай
весь каталог. Затем вызови generate_scenario и проверь файл через inspect_map,
inspect_encounters и preview_map; текстовый обзор подходит, если PNG недоступен.
Верни путь к .h3m и результаты проверок.

Работай через MCP без Computer Use и без правки кода проекта. Неподдержанные
механики замени доступными с пояснением. Не заявляй, что боевой баланс
подтверждён автоматической проверкой или реальным прохождением.
