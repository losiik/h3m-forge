# Локальный MCP-сервер h3m-forge

Для проверки в других агентах: [Claude Desktop, вкладка Code, Claude Code в терминале и ChatGPT](mcp-other-agents.md).

MCP даёт агенту готовые операции над картами: ему не нужно каждый раз писать
временный Python-скрипт для чтения заголовка, подсчёта объектов или сборки карты.
Это интерфейс к библиотеке, генератору миров, генератору собственных сюжетов
и отдельной «Одиссее». Сервер сам не вызывает
языковую модель и не управляет окном редактора HotA.

## Установка и запуск

Из корня проекта, Python 3.12+:

```powershell
python -m venv .venv-mcp
& .\.venv-mcp\Scripts\python.exe -m pip install -e '.[mcp]'
& .\.venv-mcp\Scripts\python.exe main.py
```

Если окружение уже создано, пропустите первую команду. Для тестов установите
`.[mcp,dev]` вместо `.[mcp]`. Активация окружения не нужна.

В PyCharm выберите `.venv-mcp\Scripts\python.exe` как интерпретатор проекта
и запустите корневой `main.py` кнопкой Run. Папка проекта определяется
автоматически; `--workspace` позволяет выбрать другую. Прежний запуск
`python -m h3m.mcp_server --workspace PATH` также поддерживается.
[Подробная настройка PyCharm и зависимостей](mcp-other-agents.md).

Последняя команда ждёт MCP-сообщения на stdin. Для обычного использования её
запускает клиент автоматически. Доступен также entry point `h3m-forge-mcp`.
Клиент не присоединяется к процессу, уже запущенному в окне Run; HTTP-адреса нет.
Без `--game-dir` используется `H3_GAME_DIR` и стандартный поиск установленной игры.
Без игры доступны PNG-обзор, текстовая разметка, просмотр и редактирование метаданных собственных карт;
генерация требует референсных карт HotA.

Основа — [официальный MCP Python SDK](https://py.sdk.modelcontextprotocol.io/),
дополнительная зависимость `mcp>=2.1.1,<3`. Ядро формата сохраняет нулевые
обязательные внешние зависимости. Проверенная версия SDK: 2.1.1.
Локальный транспорт — [stdio](https://py.sdk.modelcontextprotocol.io/run/):
без сетевого порта, отдельного фонового сервиса и API-ключей. stdout занят
протоколом, диагностические сообщения идут в stderr.

## Подключение к Codex

Готовая таблица с путями этой машины: [examples/codex.mcp.toml](../examples/codex.mcp.toml).
Она предназначена для `.codex/config.toml` в корне проекта. При переносе измените
путь к Python, workspace и игре. Остальные настройки клиента сохраняются.
Codex загружает настройки проекта только для доверенного проекта;
это описано в [официальной документации MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Время запуска ограничено 30 секундами, одного вызова — 600 секундами: первый
запрос генерации собирает каталог шаблонов и вариантов рельефа. Инициализация
MCP не читает весь корпус карт. Кэш лежит в `out/mcp/world-assets.json`, после
первой генерации каталог также хранится в памяти процесса. Чтобы перечитать
изменившийся корпус во время работы, перезапустите сервер.

После добавления конфигурации откройте новую сессию проекта или перезапустите
клиент, чтобы он заново загрузил сервер. Наличие записи в конфигурации и успешный
тест протокола ещё не означают, что уже открытая сессия получила новые инструменты.

Другой MCP-клиент запускает тот же executable с теми же аргументами. Например,
для клиентов с JSON-конфигурацией `mcpServers`:

```json
{
  "mcpServers": {
    "h3m-forge": {
      "command": "C:/Users/serge/PycharmProjects/h3m-forge/.venv-mcp/Scripts/python.exe",
      "args": ["-m", "h3m.mcp_server", "--workspace", "C:/Users/serge/PycharmProjects/h3m-forge", "--game-dir", "C:/Games/Heroes of Might and Magic III Complete"],
      "env": {"PYTHONUTF8": "1"}
    }
  }
}
```

## Инструменты

| Инструмент | Назначение |
|---|---|
| `project_status` | Пути, наличие HotA и доступные операции. |
| `catalog_search` | Поиск по категории, русскому/английскому названию, ID и свойствам; фильтры по тегу и фракции (русское имя или английский ключ), пагинация. 361 карточка без игры и сети; `ruleset`: HotA 1.8.0/1.8.1 (по умолчанию 1.8.1). Для наборов: `category=artifacts`, `tag=сборный`. |
| `catalog_get` | Подробная карточка артефакта, существа или заклинания: справочные характеристики, эффекты, источники, статус сверки с HotA и поддержка генератором. Неизвестный ID даёт `found=false`. |
| `skill_catalog` | Проверенные ID 0–27, русские/английские названия, уровни и предпосылки Воскрешения; поиск по названию, ключу или номеру. Работает без игры. |
| `inspect_hero_skills` | Навыки героев, темниц, случайных героев и предустановок из H3M: ID, названия, уровни, источник, неизвестные значения и ошибки; пагинация. |
| `list_maps` | Карты в `out/` или установленном `Maps/`, с пагинацией. |
| `inspect_map` | Название, описание, игроки, версия, числа объектов, SHA-256 и бинарные проверки. |
| `preview_map` | PNG и текстовый обзор всего уровня или участка: рельеф, маски препятствий, объекты, координаты и награды. Без игры и Computer Use. |
| `list_objects` | Координаты, типы, подтипы и DEF; фильтры по типу и уровню. |
| `validate_map` | Полнота разбора, побайтовая пересборка, координаты якорей и ссылки на шаблоны. |
| `generate_world` | Обычный мир по графу зон: размер, seed, биомы, игроки, связи. |
| `scenario_catalog` | Допустимые почвы, задания, боевые заклинания, порядок ресурсов и доступные ID существ с именами DEF; существа выдаются страницами. |
| `generate_scenario` | Собственное одиночное приключение из графа 2–16 глав. `spec.balance_profile="fixed"` включает фиксированную охрану и награды на 80–200%, без роста, случайных улучшений и найма. `report.balance` отделяет проверку настроек от игрового баланса. |
| `generate_odyssey` | Переработка 12: охраняемый магический колодец у развилки Сциллы и Харибды (30 воров, 15 кочевников), 5 древних чудищ после сирен, 200 сирен и Чаша тишины (Мудрость до экспертной, +30 маны); меч Эола, мастерская на Трое, редкие награды и усиленный Антиной. 41 столкновение с учётом необязательных; фактический баланс и найм ИИ требуют игрового прогона. |
| `edit_metadata` | Новая копия карты с другим названием и/или описанием. |
| `inspect_texts` | Указатели, бутылки, диалоги заданий и сообщения событий с координатами и этапами. |
| `inspect_encounters` | Охрана, награды, ресурсы, армия и активация событий; численность и ID монстров. HotA revision 9. |
| `edit_monster` | Новая копия с изменённой численностью и/или сообщением выбранного отряда; его ID и награда сохраняются. HotA revision 9. |

Ресурс `h3m://world-example` содержит минимальную спецификацию двух игроков.
Ресурс `h3m://scenario-example` содержит минимальное одиночное приключение;
его можно получить и после установки пакета вне исходного репозитория.
Полный контракт и примеры: [сюжетный генератор](scenario-generator.md).

## Смотреть карту без окна HotA

Справочник игры описан в [game-catalog.md](game-catalog.md). Для двух новых
инструментов публикуется подробная `outputSchema`, включая характеристики,
эффекты, уровни магии и источники. Схемы и реальные примеры можно выгрузить:

```powershell
.venv-mcp/Scripts/python.exe tools/export_mcp_catalog.py
```

Результаты: `out/mcp-tools.schema.json` и `out/mcp-catalog.examples.json`.
Команда выполняет только чтение; карту не генерирует и не изменяет.

`preview_map` читает сам `.h3m` и возвращает стандартный MCP `ImageContent`
с PNG, а также JSON в `structuredContent` и текстовый блок для совместимости.
Изображение — схема автора: видны скрытые события, рельеф, фактические маски
препятствий и буквенные обозначения интерактивных объектов. Это не скриншот
игры и не имитация её графики. Никакие дополнительные библиотеки изображений
не нужны; генерация PNG работает на стандартной библиотеке Python.

Обзор уровня:

```json
{"path":"out/Odyssey-Homecoming-Labyrinth.h3m","output":"both","limit":10}
```

Точное описание и клеточная разметка развилки без передачи изображения:

```json
{"path":"out/Odyssey-Homecoming-Labyrinth.h3m","x":63,"y":49,"width":9,"height":12,"output":"text","include_grid":true}
```

`output`: `both`, `image` или `text`. Для `image` сохраняется краткая легенда;
список объектов исключается. Уровень задаётся `level=0` или `1`. Координаты
отсчитываются с нуля, X растёт на восток, Y — на юг. Якорь спрайта и клетка
посещения выдаются раздельно. Индексы объектов совпадают с `list_objects`.
Разметка `include_grid` точная, один символ на клетку; предел участка 48×48
защищает от огромного ответа. Список объектов листается через `offset` и
`next_offset`; сообщения ограничены 180 символами, полные доступны через
`inspect_texts`. Масштабированный обзор PNG ограничен примерно 964 пикселями.

Это экономит вызовы управления окном и позволяет агентам без Computer Use
осматривать карты. Проверка принятия формата движком и игровые испытания
остаются отдельными этапами. После обновления кода уже запущенный MCP-процесс
нужно перезапустить, чтобы он объявил новый инструмент.
В схеме `generate_world` перечислены поля и ограничения; все зоны должны быть
связаны, игроки нумеруются подряд от 0, каждому назначается ровно одна зона.
Связи обычного мира — сухопутные мосты, сюжетных блокировок в этом генераторе нет.

Примеры запросов агенту:

- «Через h3m-forge покажи морских монстров последней Одиссеи: object_id 54, level 0».
- «Создай карту 72×72 с двумя игроками, снежным и травяным островами, seed 42».
- «Собери Одиссею и покажи результат проверки преждевременного доступа к островам».
- «Создай через generate_scenario историю спасения маяка: морской бой,
  ремонт за припасы, необязательное спасение моряков и финальное сражение».
- «Сделай копию этой карты с названием “Дорога домой”».

## Файлы, изменения и границы проверок

Относительные входные пути считаются от workspace. Чтение ограничено `.h3m`
в workspace и каталоге Maps выбранной игры; проверяется разрешённый абсолютный
путь, включая разрешение символьных ссылок. Лимиты файла: 32 MiB сжатых и
64 MiB распакованных данных. Это локальный инструмент для собственных карт,
не изолированная песочница для анализа враждебных файлов.

Каждая успешная генерация или правка создаёт новый каталог
`out/mcp/<операция>-<UTC-время>-<идентификатор>/` с `map.h3m` и `report.json`.
Сначала карта проверяется и записывается во временный каталог, затем каталог
публикуется переименованием. При ошибке публикации временный каталог удаляется.
Установленные карты и предыдущие сборки не перезаписываются. Установку карты
в игровой Maps эта версия MCP не выполняет.

`edit_metadata` требует SHA-256 из свежего `inspect_map`: правка устаревшей версии
отклоняется. Неполностью разобранные карты доступны для анализа, но не для правки.
Строки записываются в CP1251; эмодзи и другие неподдерживаемые символы отклоняются.
`edit_monster` также требует `expected_sha256` и индекс объекта из
`inspect_encounters`. Численность — целое число 1–65535. Неподдерживаемые
форматы отклоняются; изменение отряда не считается проверкой боевого баланса.
Для собственного сценария армия героя, задания, почвы и награды меняются
в спецификации `generate_scenario` и собираются заново. Произвольной правки
этих свойств в уже существующей чужой карте через MCP пока нет.

`full_parse`, `roundtrip`, структурная корректность, проверка сценария и проверка
в игре — разные результаты. `validate_map` не доказывает отсутствие обходов и
тупиков. Генератор «Одиссеи» дополнительно выполняет свои проверки маршрута,
сохранённые в `report`; SDK не добавляет их к произвольной чужой карте.
Нативный редактор и полное игровое прохождение этим сервером не проверяются.
В актуальной «Одиссее» поле `barriers` описывает ландшафтные преграды,
`landings` — 16 проверенных пристаней, `pacing` — длины морских переходов.
Это проверки данных карты; они не означают полный игровой прогон.
Тексты внутри карт рассматриваются как данные сценария, а не инструкции агенту.

`inspect_texts(path, offset, limit)` читает тексты указателей, бутылок, встреч,
квестов и глобальных событий в поддерживаемых форматах RoE/AB/SoD/HotA.
Возвращает координаты, тип источника и этап диалога (`first`, `repeat`,
`completed`), чтобы изучать навигацию чужих карт. Это 11-й инструмент MCP.
Следуйте `next_offset`: ответ разбит на страницы. `full_parse` и `errors`
показывают границы извлечения; расширенные скрипты, городские события и
биографии сюда не входят. Исходные карты не изменяются.

В актуальной «Одиссее» `guidance.revision=2`: общий обзор и глаза магов
удалены. `labyrinth` описывает морскую сеть, преграды и боковые бухты,
`balance` — стартовую армию, заклинания и численность противников.
`crown_dependency_removed` отмечает замену задания на корону боевой задачей.
`mandatory_without_optional` подтверждает прохождение модели без дополнительных наград.

## Проверка подключения

```powershell
.venv-mcp/Scripts/python.exe tools/check_mcp.py
# Полная проверка с настоящими генерациями на установленной HotA:
.venv-mcp/Scripts/python.exe tools/check_mcp.py --generate
# Автотесты без необходимости иметь игру:
.venv-mcp/Scripts/python.exe -m pytest tests/test_service.py tests/test_mcp_server.py
```

`check_mcp.py` запускает отдельный процесс и обращается к нему официальным
MCP-клиентом. Отчёт сохраняется в `out/mcp-smoke.json`. При `--generate` он
содержит пути и контрольные суммы трёх новых карт; для «Одиссеи» проверяются
запрет раннего доступа, порядок морских боёв и модель прохождения глав.
Дополнительно проверяются чтение столкновений и изменение монстра через stdio:
численность и сообщение меняются, ID задания и награда сохраняются, исходник неизменен.
Для самостоятельного сценария проверяются прохождение основной линии без
необязательной ветки, доступность всей ветки и создание руководства.

Для фиксированных боёв передайте `"balance_profile": "fixed"` в объекте
`spec` инструмента `generate_scenario`. Полный пример:
[fixed-company.json](../examples/fixed-company.json). Профиль доступен также
через обычный Python/CLI-вход. Без параметра действует прежний `standard`.
«Одиссея» редакции 12 имеет отдельный баланс: по просьбе игрока рост
стрелков у финального противника восстановлен. Профиль `fixed` других
сюжетных карт сохраняет запрет найма.
После обновления перезапустите подключение MCP, чтобы клиент получил новую
схему. Режим сохраняет заданные автором количества и не гарантирует победу
в каждом бою; пополнение отряда нужно предусмотреть в наградах.


## Навыки: запрос, настройка и проверка

1. Вызвать `skill_catalog({"query":"земля"})`: результат — `id=17`,
   `key=earth_magic`, `name_ru=Магия земли`. Огонь — ID 14.
2. Передать `hero_skills` в спецификации `generate_scenario`, например:
   `"hero_skills": [[0,3],[2,3],[5,3],[23,2],[22,2],[17,2],[7,2]]`.
   Это **полный список** стартовых навыков, заменяющий значения по умолчанию.
   Пустой список означает отсутствие навыков. Допустимо не более 8 уникальных
   ID 0–27 с уровнями 1 (базовый), 2 (продвинутый), 3 (экспертный).
   При отсутствии параметра сохраняется прежний набор из пяти навыков.
3. Вызвать `inspect_hero_skills({"path":"путь из результата генерации"})`.
   Проверять название, ID, уровень и `skills_source`, а не только номер.

Для Воскрешения (заклинание 38) продвинутая Земля (навык 17, уровень 2)
сохраняет поднятых живых воинов после победы. Продвинутая Мудрость (7, 2)
позволяет изучать заклинания четвёртого уровня. Это разные пространства ID:
навык 17 — Земля, заклинание 17 — Молния.

`permanent_resurrection_skill_ready` проверяет только уровень Земли;
`can_learn_level_four_spells` — только Мудрость. Они не обещают наличие
книги, самого заклинания, достаточной маны или победу в бою.

`skills_source=object` означает явные настройки объекта;
`predefined_hero` — настройки героя в общем блоке карты.
`game_defaults_unresolved` и `skills=null` означают, что навыки из игровых
таблиц не определены; это **не** отсутствие навыков. Явно пустой набор — `[]`.
Неизвестные номера сохраняются с `known=false` и пустым названием.
Справочник покрывает проверенные базовые навыки 0–27; дополнительные навыки
поздних версий HotA пока не расшифровываются и не принимаются генератором.
Читаются стартовые настройки `.h3m`, а не текущее состояние сохранённой партии.
