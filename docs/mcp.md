# Локальный MCP-сервер h3m-forge

MCP даёт агенту готовые операции над картами: ему не нужно каждый раз писать
временный Python-скрипт для чтения заголовка, подсчёта объектов или сборки карты.
Это интерфейс к существующей библиотеке и двум генераторам. Сервер сам не вызывает
языковую модель и не управляет окном редактора HotA.

## Установка и запуск

Из корня проекта, Python 3.12+:

```powershell
python -m venv .venv-mcp
.venv-mcp/Scripts/python.exe -m pip install -e '.[mcp,dev]'
.venv-mcp/Scripts/python.exe -m h3m.mcp_server --workspace 'C:\Users\serge\PycharmProjects\h3m-forge' --game-dir 'C:\Games\Heroes of Might and Magic III Complete'
```

Последняя команда ждёт MCP-сообщения на stdin. Для обычного использования её
запускает клиент автоматически. Доступен также entry point `h3m-forge-mcp`.
Без `--game-dir` используется `H3_GAME_DIR` и стандартный поиск установленной игры.
Без игры доступны просмотр и редактирование метаданных собственных карт;
генерация требует референсных карт HotA.

Основа — [официальный MCP Python SDK](https://py.sdk.modelcontextprotocol.io/),
дополнительная зависимость `mcp>=2.1.1,<3`. Ядро формата сохраняет нулевые
обязательные внешние зависимости. Проверенная версия SDK: 2.1.1.
Локальный транспорт — [stdio](https://py.sdk.modelcontextprotocol.io/run/):
без сетевого порта, отдельного фонового сервиса и API-ключей. stdout занят
протоколом, диагностические сообщения идут в stderr.

## Подключение к Codex

Готовая таблица с путями этой машины: [examples/codex.mcp.toml](../examples/codex.mcp.toml).
Она предназначена для `.codex/config.toml` в корне проекта. При переносе измените
путь к Python, workspace и игре. Остальные настройки клиента сохраняются.
Codex загружает настройки проекта только для доверенного проекта;
это описано в [официальной документации MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

Время запуска ограничено 30 секундами, одного вызова — 600 секундами: первый
запрос генерации собирает каталог шаблонов и вариантов рельефа. Инициализация
MCP не читает весь корпус карт. Кэш лежит в `out/mcp/world-assets.json`, после
первой генерации каталог также хранится в памяти процесса. Чтобы перечитать
изменившийся корпус во время работы, перезапустите сервер.

После добавления конфигурации откройте новую сессию проекта или перезапустите
клиент, чтобы он заново загрузил сервер. Наличие записи в конфигурации и успешный
тест протокола ещё не означают, что уже открытая сессия получила новые инструменты.

Другой MCP-клиент запускает тот же executable с теми же аргументами. Например,
для клиентов с JSON-конфигурацией `mcpServers`:

```json
{
  "mcpServers": {
    "h3m-forge": {
      "command": "C:/Users/serge/PycharmProjects/h3m-forge/.venv-mcp/Scripts/python.exe",
      "args": ["-m", "h3m.mcp_server", "--workspace", "C:/Users/serge/PycharmProjects/h3m-forge", "--game-dir", "C:/Games/Heroes of Might and Magic III Complete"],
      "env": {"PYTHONUTF8": "1"}
    }
  }
}
```

## Инструменты

| Инструмент | Назначение |
|---|---|
| `project_status` | Пути, наличие HotA и доступные операции. |
| `list_maps` | Карты в `out/` или установленном `Maps/`, с пагинацией. |
| `inspect_map` | Название, описание, игроки, версия, числа объектов, SHA-256 и бинарные проверки. |
| `list_objects` | Координаты, типы, подтипы и DEF; фильтры по типу и уровню. |
| `validate_map` | Полнота разбора, побайтовая пересборка, координаты якорей и ссылки на шаблоны. |
| `generate_world` | Обычный мир по графу зон: размер, seed, биомы, игроки, связи. |
| `generate_odyssey` | Переработка 4, 72×72: короткие проливы, шляпа адмирала, три платных альтернативы охраняемым припасам, отчёты `pacing` и `shore_access`. Сохраняет 23 столкновения и девять основных заданий. |
| `edit_metadata` | Новая копия карты с другим названием и/или описанием. |
| `inspect_encounters` | Охрана, награды, ресурсы, армия и активация событий; численность и ID монстров. HotA revision 9. |
| `edit_monster` | Новая копия с изменённой численностью и/или сообщением выбранного отряда; его ID и награда сохраняются. HotA revision 9. |

Ресурс `h3m://world-example` содержит минимальную спецификацию двух игроков.
В схеме `generate_world` перечислены поля и ограничения; все зоны должны быть
связаны, игроки нумеруются подряд от 0, каждому назначается ровно одна зона.
Связи обычного мира — сухопутные мосты, сюжетных блокировок в этом генераторе нет.

Примеры запросов агенту:

- «Через h3m-forge покажи морских монстров последней Одиссеи: object_id 54, level 0».
- «Создай карту 72×72 с двумя игроками, снежным и травяным островами, seed 42».
- «Собери Одиссею и покажи результат проверки преждевременного доступа к островам».
- «Сделай копию этой карты с названием “Дорога домой”».

## Файлы, изменения и границы проверок

Относительные входные пути считаются от workspace. Чтение ограничено `.h3m`
в workspace и каталоге Maps выбранной игры; проверяется разрешённый абсолютный
путь, включая разрешение символьных ссылок. Лимиты файла: 32 MiB сжатых и
64 MiB распакованных данных. Это локальный инструмент для собственных карт,
не изолированная песочница для анализа враждебных файлов.

Каждая успешная генерация или правка создаёт новый каталог
`out/mcp/<операция>-<UTC-время>-<идентификатор>/` с `map.h3m` и `report.json`.
Сначала карта проверяется и записывается во временный каталог, затем каталог
публикуется переименованием. При ошибке публикации временный каталог удаляется.
Установленные карты и предыдущие сборки не перезаписываются. Установку карты
в игровой Maps эта версия MCP не выполняет.

`edit_metadata` требует SHA-256 из свежего `inspect_map`: правка устаревшей версии
отклоняется. Неполностью разобранные карты доступны для анализа, но не для правки.
Строки записываются в CP1251; эмодзи и другие неподдерживаемые символы отклоняются.
`edit_monster` также требует `expected_sha256` и индекс объекта из
`inspect_encounters`. Численность — целое число 1–65535. Неподдерживаемые
форматы отклоняются; изменение отряда не считается проверкой боевого баланса.
Произвольного изменения ландшафта, армий героев и заданий через MCP пока нет: такие
доработки делаются в коде генератора и затем проверяются новой сборкой.

`full_parse`, `roundtrip`, структурная корректность, проверка сценария и проверка
в игре — разные результаты. `validate_map` не доказывает отсутствие обходов и
тупиков. Генератор «Одиссеи» дополнительно выполняет свои проверки маршрута,
сохранённые в `report`; SDK не добавляет их к произвольной чужой карте.
Нативный редактор и полное игровое прохождение этим сервером не проверяются.
Тексты внутри карт рассматриваются как данные сценария, а не инструкции агенту.

## Проверка подключения

```powershell
.venv-mcp/Scripts/python.exe tools/check_mcp.py
# Полная проверка с настоящими генерациями на установленной HotA:
.venv-mcp/Scripts/python.exe tools/check_mcp.py --generate
# Автотесты без необходимости иметь игру:
.venv-mcp/Scripts/python.exe -m pytest tests/test_service.py tests/test_mcp_server.py
```

`check_mcp.py` запускает отдельный процесс и обращается к нему официальным
MCP-клиентом. Отчёт сохраняется в `out/mcp-smoke.json`. При `--generate` он
содержит пути и контрольные суммы обеих новых карт; для «Одиссеи» проверяются
запрет раннего доступа, порядок морских боёв и модель прохождения глав.
Дополнительно проверяются чтение столкновений и изменение монстра через stdio:
численность и сообщение меняются, ID задания и награда сохраняются, исходник неизменен.
